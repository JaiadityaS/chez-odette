0) THE 30-SECOND PITCH (what we built and why it wins)
--------------------------------------------------------------------------------
"Chez Amélie — back of house" is the operations dashboard a solo French baker
uses to run her shop: supplies, menu, live customer orders, and messages, all on
one board. It works fully by hand — every fix is a normal button click.

On top of that, the SAME dashboard exposes 16 WebMCP tools. An AI agent (we test
in the ChatGPT app's in-app browser) DISCOVERS those tools at runtime and CHAINS
them to clear a morning crisis — with no bespoke, hardcoded "fix my morning" flow
anywhere in the code.

Why this is a strong WebMCP entry (say a version of this in the video):
  • It's ACTION, not scraping. A scraper can read the page; it cannot reorder a
    supplier, mark an order ready, or text a customer. These are stateful writes.
  • The board updates in REAL TIME. Alerts are derived live from state, so a
    scraper snapshotting HTML is always stale. Fix the cause and the alert dies.
  • DISCOVERY beats hardcoding. Two of the tools (set_price, set_shop_open) have
    NO buttons on the screen. The agent can still find and use them — proof that
    hardcoding an API call per feature is a nightmare, and MCP lets the agent
    discover capabilities and compose them itself.

HARD RULE for the video: this is a SIMULATED shop. No real money, no real
payments, no real supplier. Do not imply otherwise on camera.

1) WHAT'S ON THE SCREEN (so you can narrate it accurately)
--------------------------------------------------------------------------------
Left sidebar (dark): the "Chez Amélie / Back of house" mark, nav (Today, Orders,
Menu, Inventory, Messages), an agent/manual pill, and "Brioche" the shop cat
sprite at the bottom (it breathes, blinks, flicks its tail — that's intentional
charm, not a bug).

Main board opens IN CRISIS — lots of red. Top to bottom:
  • KPI strip: Needs attention, Open tickets, In the queue, On the menu.
    Numbers are in a modern typeface (Space Grotesk) on purpose — the one
    "modern" accent against the classical serif. Everything else is sentence
    case, no ALL CAPS anywhere. Don't "fix" that; it's a deliberate design call.
  • "Needs attention" — the red task inbox. Each row has a pulsing red dot and a
    one-click action button. THIS is what goes red → green during the demo.
  • "Live orders" — a table of customer orders with status chips.
  • Inventory / Menu / Messages panels.
  • Activity log — every action (by you OR the agent) lands here with a little
    animation. GREAT for the camera: it's the visible paper trail of the agent
    working.

THE EXACT OPENING CRISIS (memorize this — it's what the agent must clear):
  RED (7):
    1. Butter is out  (supplier: Beurre & Co)
    2. Walnut levain still on the menu   (needs butter, which is out)
    3. Butter croissant still on the menu (needs butter)
    4. Chocolate tart still on the menu   (needs butter)
    5. Can't fulfil Marc's order   A-118 (2 butter croissants)
    6. Can't fulfil Sofia's order  A-119 (walnut levain)
    7. Leïla's order A-114 is overdue (sourdough, was due 8:00)
  AMBER (3):
    8. Walnuts running low (supplier: Périgord Nuts)
    9. Marc is waiting — "Is my croissant order still good for 8:30?"
   10. Théo is waiting — "Any walnut bread I can grab Saturday?"

So the board opens at roughly: Needs attention 10, Open tickets 3, etc.


--------------------------------------------------------------------------------
2) HOW ONE FIX CASCADES (the "wow" — the agent looks smart because the board is)
--------------------------------------------------------------------------------
The single most impressive moment: reordering butter clears SIX red alerts at
once, because the alerts are derived, not hardcoded.

  • reorder_supply("butter")  →  butter goes back In stock. That instantly kills:
      - "Butter is out"
      - all 3 "still on the menu" item alerts (butter no longer missing)
      - both "can't fulfil" order alerts for Marc (A-118) and Sofia (A-119)
    That's 6 reds gone from ONE action.

  • mark_order_ready("A-114")  →  clears the last red (Leïla's overdue order).

  Board is now fully out of the red. Then the ambers:
  • reorder_supply("walnuts")     →  clears "Walnuts running low"
  • reply_to_message("m1", ...)   →  clears "Marc is waiting"
  • reply_to_message("m2", ...)   →  clears "Théo is waiting"
  • (nice-to-have) mark_order_ready("A-118") and ("A-119") to tidy the queue.

Result: green board. Say on camera: "One instruction. The agent read the board,
discovered the tools, and worked the crisis in order — and every fix propagated
live." Note: outward actions (reorder, refund, reply, text) have a deliberate
~0.7–1.1s "doing the work" pause so it reads as real labour, not an instant flip.

3) THE 16 WEBMCP TOOLS (for the "discovery" beat / on-screen callout)
--------------------------------------------------------------------------------
Registered via  document.modelContext.registerTool(...)  in the page itself.
READ/TRIAGE:  ping · get_alerts · get_supplies · get_menu · get_orders ·
              get_messages · items_using_supply
ACTIONS:      reorder_supply · mark_86 · put_back_on_menu · refund_order ·
              mark_order_ready · reply_to_message · text_customer
DISCOVERY-ONLY (no button on the board): set_price · set_shop_open

Optional kicker shot: after the board is green, in the ChatGPT chat type
"raise the chocolate tart to 7 euros" — the agent uses set_price, a tool with NO
UI button. That's the cleanest possible proof of runtime discovery.

4) TEST SETUP — GET THE AGENT TALKING TO THE BOARD
--------------------------------------------------------------------------------
Primary runtime = the ChatGPT app's in-app browser (this is where WebMCP works).
  a. Open ChatGPT (the app), open its in-app browser, go to:
        https://chez-odette-tau.vercel.app/
  b. Confirm the crisis board loads (lots of red).
  c. In the chat, ask the agent to work the board (prompts in section 6).
  d. The agent should call the tools; the board updates live behind/beside chat.

Chrome alternative (if you film in Chrome instead): enable the flag at
    chrome://flags/#enable-webmcp-testing
then load the site. (ChatGPT app is the more reliable demo runtime — prefer it.)

To show ChatGPT's reasoning ("what it's thinking") on camera: ask it explicitly
to narrate — e.g. "work the board one step at a time and say what you're doing
and why before each action." That produces visible, filmable step-by-step text.

IMPORTANT REAL-TIME CAVEAT: state is in-memory PER TAB. Two separate windows do
NOT sync. So film the board and the chat in the SAME browser view (the ChatGPT
in-app browser handles this — the board and the chat are the same session).
To restart the crisis for another take, just RELOAD the page (fresh seed).

6) PROMPTS TO TYPE INTO CHATGPT (copy-paste these)
--------------------------------------------------------------------------------
MASTER PROMPT (use this one for the main take):
  "The butter delivery didn't come this morning. Work my board one step at a
   time — say what you're doing and why before each action — until nothing's in
   the red. Reorder what's out, take care of the orders, and reply to anyone
   who's waiting, in a warm voice."

If it stalls or you want to steer, follow-ups:
  "Start by checking the alerts, then fix the most urgent thing first."
  "Now handle the overdue order."
  "Reply to the two waiting customers."

DISCOVERY KICKER (after green):
  "Raise the chocolate tart to 7 euros."     (uses set_price — no button exists)
  or  "Actually, close the shop for the day." (uses set_shop_open — no button)

7) IF THE AGENT MISBEHAVES ON CAMERA (fallbacks)
--------------------------------------------------------------------------------
• Agent does nothing / doesn't see tools: reload the page inside the ChatGPT
  in-app browser; confirm you're on the live URL; try the prompt again. In
  Chrome, confirm the webmcp-testing flag is on.
• Agent refunds instead of reordering: that's still valid (refund_order exists),
  but for the cleanest story re-run and add "prefer to reorder and fulfil rather
  than refund" to the prompt.
• You want a clean board again: just RELOAD — it reseeds the full crisis.
• Manual proof shot: every red row has its own button, so you can always fix a
  row by hand on camera if you want to show the non-AI path.
• There's a dev-only manual tool tester at  ?harness=1  (append to the URL) if
  you ever need to fire a specific tool by hand off-camera to reset state.
